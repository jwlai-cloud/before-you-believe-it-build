# Before You Believe It — three-minute demo voice-over

**Target runtime:** 2:45–2:55, plus a 5-second safety buffer if the submission limit is exactly three minutes. The family activity itself takes 5–7 minutes; this is the shorter submission video.
**Voice direction:** warm, calm, curious adult narrator; never perform a child’s voice or imply that AI is an authority.

| Time | Screen action | Narration |
| --- | --- | --- |
| 0:00–0:15 | Title, then the revised purpose panel. | “A weekend question is changing. When AI gives a confident answer, how can a child learn to think with it—not simply trust it? Before You Believe It turns that moment into a short parent-and-child practice.” |
| 0:15–0:35 | The five-step rail and the Floating City claim. | “In about six minutes, a family follows one visible path: Think, Push Back, Check, Make, and Own. There are no points, no answer key, and no model answer. The goal is a conversation a parent can understand and a child can lead.” |
| 0:35–0:55 | Select a child question. | “We start with a plausible AI claim: floating cities are better for the planet. Instead of asking whether it is correct, the child chooses what makes them pause. That question becomes the starting point.” |
| 0:55–1:18 | Push Back: claim splitting and hidden assumption. | “Next, the claim splits into parts. Together, parent and child find the assumption doing too much work—here, that untouched means no effects at all. The parent gets a gentle nudge, not a script.” |
| 1:18–1:42 | Check: select a clue and show evidence link. | “Then they check. The canvas places a systems clue, another view, and an open question beside the claim. The child connects one clue to their thinking. AI has prepared material; it has not decided what to believe.” |

| 2:45–2:55 | Preset fallback, final title and links. | “And if live AI is unavailable, the complete preset mission still works. Before You Believe It helps families build the habit that matters in the AI age: pause, question, check, and think together.” |

## Capture checklist

1. Record static clips first: title/purpose, child choice, claim split, evidence link, working answer, and receipt.
2. Use a clean browser window at a consistent desktop resolution; hide extensions, notifications, bookmarks, and unrelated tabs.
3. Before the live take, confirm the deployed endpoint and judge code work. Use a non-personal topic such as `school gardens`; never capture the access code, API key, or private child information.
4. Record the live generation as its own clip. Leave two seconds before and after the result so it can be trimmed or replaced if the network is slow.
5. Add captions for the differentiation claim, the five steps, “child answer stays on device,” and the final URL. Keep captions useful with the sound off.
6. Generate premium TTS only after final timing is approved. The final audio service and licensed voice need explicit approval; no synthetic voice has been generated in this repository yet.
